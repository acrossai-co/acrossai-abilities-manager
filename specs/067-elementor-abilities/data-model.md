# Data Model: Elementor Ability Suite

**Feature**: 067-elementor-abilities
**Date**: 2026-08-13

This feature introduces **no new persistent storage**. All state lives in existing WordPress storage (`wp_posts`, `wp_postmeta`, `wp_options`, Elementor Pro's own tables) and is manipulated in-memory. This document describes the **logical entities** that appear in ability inputs and outputs.

---

## Entity: `Elementor Document`

A WordPress post carrying Elementor content — a page, post, template, popup, header, footer, single, or archive.

| Field | Type | Source |
|---|---|---|
| `post_id` | `int` (≥ 1) | `wp_posts.ID` |
| `post_type` | `string` | `wp_posts.post_type` — one of `page`, `post`, `elementor_library`, or any Elementor-editable CPT |
| `edit_mode` | `string` | `_elementor_edit_mode` post meta — always `builder` for Elementor documents |
| `template_type` | `string` | `_elementor_template_type` post meta — one of `wp-page`, `wp-post`, `page`, `section`, `popup`, `header`, `footer`, `single`, `archive`, `kit` |
| `elementor_data` | `array<Element>` | `_elementor_data` post meta (JSON-decoded) — the root ordered list of top-level elements |
| `page_settings` | `array<string, mixed>` | `_elementor_page_settings` post meta — document-level settings (layout, title, background, custom CSS) |
| `elementor_version` | `string` | `_elementor_version` post meta — version at last save |
| `wp_page_template` | `string` | `_wp_page_template` post meta — often `elementor_canvas` or `elementor_header_footer` |
| `css_cache` | `string?` | `_elementor_css` post meta — generated CSS blob (invalidated on write) |

**Validation**:
- `post_id` must resolve via `get_post()`.
- `post_type` must NOT be one of the internal types (revision, nav_menu_item, custom_css, customize_changeset, oembed_cache, user_request) — FR-037.
- `post_type` must be public / show_in_rest / show_ui.
- `elementor_data` must decode to a valid JSON array; corrupt documents surface a structured error and can only be overwritten with `force_replace=true`.

**Persistence rules**:
- All writes to `_elementor_data` MUST wrap the JSON in `wp_slash()` before `update_post_meta()` — R4.
- After every write, invalidate cache via `Document_Repository::invalidate_cache()` — R8.

## Entity: `Element`

A single node in an Elementor Document's tree.

| Field | Type | Notes |
|---|---|---|
| `id` | `string` (7-char hex) | Unique per document, generated by Elementor. New elements get fresh IDs. |
| `elType` | `string` | One of `container`, `widget`, `section` (legacy v2), `column` (legacy v2) |
| `widgetType` | `string?` | Present only when `elType === 'widget'` — the widget's slug (e.g. `heading`, `nav-menu`, `posts`) |
| `settings` | `array<string, mixed>` | Element's settings — validated against Widget Type schema when known |
| `elements` | `array<Element>` | Ordered list of child elements — recursive |
| `isInner` | `boolean?` | For containers: whether this is a nested container |
| `editSettings` | `array<string, mixed>?` | Elementor editor-only settings (locked/hidden) |

**Additional field appended by ability outputs** (not part of stored data):
- `path`: parent-chain of IDs from root to this element, used by find/move/reorder responses.

**State transitions**:
- Created by `add-container`, `add-widget`, `add-heading` (+ 4 other widget shortcuts), `duplicate-element`, `import-template`, `insert-pattern-equivalent`.
- Modified by `update-element`, `merge-element-settings`.
- Moved by `move-element`.
- Removed by `delete-element`, `remove-element`.

**ID regeneration**:
- `duplicate-element` walks the cloned subtree and assigns fresh 7-char hex IDs to every node (source plugin: `reassign_subtree_ids()`).

## Entity: `Widget Type` (external / read-only)

An Elementor widget class registered at runtime.

| Field | Type | Source |
|---|---|---|
| `name` | `string` | `\Elementor\Widget_Base::get_name()` |
| `title` | `string` | `->get_title()` |
| `icon` | `string` | `->get_icon()` |
| `categories` | `array<string>` | `->get_categories()` |
| `controls` | `array<Control>` | `->get_controls()` — the widget's full control schema |

**Access**: `Widget_Controls::get_type($name)` — thin wrapper over `\Elementor\Plugin::$instance->widgets_manager->get_widget_types($name)`.

**Never mutated by this feature.**

---

## Entity: `Control` (schema-lookup response)

The summarised shape of one Elementor control returned by `get-widget-controls`.

| Field | Type | Notes |
|---|---|---|
| `name` | `string` | Control key (used in `settings` payload) |
| `label` | `string?` | Human-readable label |
| `description` | `string?` | Longer description if present |
| `type` | `string` | Control type — `text`, `textarea`, `number`, `slider`, `select`, `color`, `dimensions`, `media`, `gallery`, `repeater`, etc. |
| `section` | `string` | Section tab this control belongs to (e.g. `section_style`, `section_content`) |
| `default` | `mixed?` | Default value if declared |

**Filter support**: optional `search` input matches case-insensitively across `name/label/description/section/type`.

## Entity: `Elementor Template`

A post of type `elementor_library` with a template subtype.

| Field | Type | Source |
|---|---|---|
| `id` | `int` | `wp_posts.ID` |
| `title` | `string` | `wp_posts.post_title` |
| `status` | `string` | `wp_posts.post_status` (`publish`, `draft`, `trash`, `auto-draft`) |
| `template_type` | `string` | `_elementor_template_type` — `page`, `section`, `popup`, `header`, `footer`, `single`, `archive` |
| `template_sub_type` | `string?` | Elementor Pro / WooCommerce subtypes (e.g. `product`, `product-archive`) |
| `elementor_data` | `array<Element>` | Same as Elementor Document — `_elementor_data` meta |
| `conditions` | `array<Condition>?` | `_elementor_conditions` meta — display conditions (Theme Builder / Popup) |

**Lifecycle**:
- Create → `create-template`
- Read → `get-template`, `list-templates`, `find-template-for-pattern`
- Update → `update-template`, `update-theme-builder-conditions`
- Trash → `delete-template` (default) → `restore-template` (reverse) → `empty-trash` (permanent)
- Duplicate → `duplicate-template` (preserves meta + subtype + conditions)
- Portability → `export-template` (returns JSON), `import-template` (accepts JSON)

## Entity: `Elementor Kit`

A special `elementor_library` post with `template_type=kit` storing site-wide design tokens.

| Field | Type | Source |
|---|---|---|
| `id` | `int` | `wp_posts.ID` |
| `title` | `string` | `wp_posts.post_title` |
| `is_active` | `bool` | Whether this kit's ID matches `get_option('elementor_active_kit')` |
| `system_colors` | `array<{_id, title, color}>` | Kit `_elementor_page_settings.system_colors` |
| `custom_colors` | `array<{_id, title, color}>` | Kit `_elementor_page_settings.custom_colors` |
| `system_typography` | `array<{_id, title, ...}>` | Kit `_elementor_page_settings.system_typography` |
| `custom_typography` | `array<{_id, title, ...}>` | Kit `_elementor_page_settings.custom_typography` |
| `button_defaults` | `object?` | Kit-level button style defaults |
| `form_defaults` | `object?` | Kit-level form-field defaults |
| `layout_defaults` | `object?` | Kit-level layout defaults |

**Operations**: `list-kits`, `get-kit-settings`, `update-kit-settings`, `set-active-kit`.

## Entity: `Theme Builder Condition`

A display rule attached to a Theme Builder template (`_elementor_conditions` post meta).

| Field | Type | Notes |
|---|---|---|
| `type` | `string` | `include` \| `exclude` |
| `name` | `string` | Condition subject — `general`, `singular`, `archive`, `search_results`, `error_404`, `wp_page`, `post`, `product`, `product_archive` |
| `sub_name` | `string?` | Sub-condition — e.g. `in_taxonomy`, `by_author` |
| `sub_id` | `string?` | Target ID (post/term/user) |

**Operations**: `get-theme-builder-conditions`, `update-theme-builder-conditions`.

## Entity: `Elementor Custom Code Snippet` (Pro)

A post of type `elementor_snippet` storing a code snippet with location targeting.

| Field | Type | Source |
|---|---|---|
| `id` | `int` | `wp_posts.ID` |
| `title` | `string` | `wp_posts.post_title` |
| `code` | `string` | `wp_posts.post_content` |
| `location` | `string` | `_elementor_snippet_location` post meta — `head`, `body_start`, `body_end`, `footer` |
| `priority` | `int` | `_elementor_snippet_priority` post meta |
| `status` | `string` | `wp_posts.post_status` — `publish` / `draft` |

**Operations**: `list-custom-code`, `get-custom-code`, `create-custom-code`, `update-custom-code`, `delete-custom-code`. All gated on Elementor Pro (R2).

## Entity: `Elementor Form Submission` (Pro)

A record of a submitted Elementor Form widget. Stored by Elementor Pro in its own custom table (`{prefix}_e_submissions` and related).

| Field | Type | Notes |
|---|---|---|
| `id` | `int` | Submission ID |
| `form_id` | `string` | Form widget's ID |
| `form_name` | `string` | Human-readable form name |
| `post_id` | `int?` | Page the form was submitted from |
| `created_at` | `string` (datetime) | Submission timestamp |
| `values` | `array<{field, value}>?` | Optional field values (when caller requests `include_values=true`) |

**Operations**: `list-form-submissions`, `get-form-submission`, `delete-form-submission`. All gated on Elementor Pro (R2).

**Note**: reads and deletes go through Elementor Pro's own DB accessors, not custom SQL.

## Entity: `Response Envelope`

The shape returned by every ability in this feature.

| Field | Type | When present | Notes |
|---|---|---|---|
| `success` | `boolean` | always | `true` on completion, `false` on error |
| `post_id` | `int` | when post-scoped | Echoes input post_id for correlation |
| `message` | `string` | always | Human-readable summary |
| `error_code` | `string?` | on `success=false` | Machine-readable — `elementor_missing`, `elementor_pro_missing`, `post_not_found`, `element_not_found`, `invalid_widget_type`, `invalid_template_type`, `insufficient_capability`, `force_replace_required`, `force_delete_required`, `invalid_path`, `descendant_destination`, `multiple_locations`, `pattern_not_found` |
| `<payload>` | varies | on `success=true` | Ability-specific data — `data`, `element`, `elements`, `template`, `templates`, `kit`, `kits`, `controls`, `conditions`, `submission`, `submissions`, `snippet`, `snippets`, etc. |

**Rule**: when `success=false`, no payload keys are present.

## Relationships

```
Elementor Document 1 ── 1 tree of Elements
Element 1 ── 0..N Elements                    [recursive: elements[]]
Element (widget) 1 ── 1 Widget Type            [validated against Widget Type's Controls schema]
Widget Type 1 ── N Controls                    [runtime registry lookup]
Elementor Template 1 ── 0..N Conditions        [Theme Builder]
Elementor Kit 1 ── site-wide tokens            [one Kit active at a time]
Custom Code Snippet 1 ── independent           [Pro only]
Form Submission N ── 1 Form widget instance    [Pro only]
```

No relational storage introduced. `Elementor Document`, `Element`, `Widget Type`, `Elementor Template`, `Elementor Kit`, `Custom Code Snippet`, `Form Submission` are all external entities owned by WordPress / Elementor / Elementor Pro. This feature only reads/writes existing storage.
